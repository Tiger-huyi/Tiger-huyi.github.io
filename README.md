# 虎義 HUYI 个人网站

公开地址：<https://tiger-huyi.github.io/>

网站采用白、黑、粉三色的瑞士国际主义风格，内容包括个人介绍、音乐分享、最近动态、随手设计和摄影。音乐在录入时读取网易云歌曲信息，正式网站使用已经确认的静态内容，访客打开页面时不会请求歌曲详情接口。

## 第一次使用

需要 Node.js 20 或更高版本。在仓库目录执行：

```sh
npm ci
npm test
npm run build
npm run preview
```

预览地址是 <http://127.0.0.1:4173/>。停止预览时在终端按 `Ctrl+C`。

## 添加音乐

运行：

```sh
npm run music:editor
```

打开终端显示的 <http://127.0.0.1:4310/>，然后：

1. 粘贴网易云单曲链接或包含链接的分享文字。
2. 点击「提取歌曲信息」。
3. 核对歌名、歌手、封面和规范歌曲链接，填写可选推荐语。
4. 「保存为草稿」只写入本机 `.local-data/`，不会公开。
5. 「保存到待发布内容」写入 `content/music/`，仍未在线发布。
6. 运行 `npm run build` 和 `npm run preview` 检查首页与音乐归档。
7. 提交并推送，经 GitHub Pages 部署成功后才算发布。

自动提取失败时，可以在同一表单手动填写歌名、歌手和封面。必须先取得有效的歌曲编号；歌名不能为空，封面可以留空。再次导入同一首歌会更新对应记录，不会根据歌名误判其他版本。

歌曲分享链接会统一为 `https://music.163.com/song?id=歌曲编号`，不会把分享者编号和其他追踪参数放进公开内容。不要把网易云 Cookie、GitHub Token、完整分享文字或接口原始响应保存到仓库。

## 修改、隐藏或移除音乐

公开歌曲记录位于 `content/music/netease-歌曲编号.json`。优先通过维护工具修改。手工修改后运行 `npm run content:check`。

- 修改推荐语或日期：编辑对应字段并重新构建。
- 暂时隐藏：将 `visible` 改为 `false`；公共仓库历史仍可能包含该记录。
- 不显示日期：将 `showDate` 改为 `false`。
- 移除：删除对应文件后重新构建并确认首页与归档都已消失。
- 封面失效：重新提取或填写允许的 `music.126.net` 图片地址；留空时网站显示固定占位。

维护工具确认后的文字字段会列入 `lockedFields`，后续刷新元数据时不得自动覆盖推荐语和人工修改。

## 项目结构

- `src/`：首页与音乐归档模板。
- `public/`：样式、少量前端脚本和公开占位资源。
- `content/music/`：允许公开的音乐记录。
- `editor/`：只在本机使用的维护界面。
- `scripts/`：链接解析、内容校验、静态构建与本地服务。
- `test/`：链接、安全边界、内容和构建测试。
- `dist/`：构建产物，由 GitHub Pages 发布；不提交。
- `DESIGN.md`：颜色、字体、网格和组件规则。
- `og-source.svg` / `og.png`：网站分享图源文件与发布图片。

## 页面与路径

- `/`：首页。
- `/music/`：音乐归档，超过 12 首时生成分页。
- `/updates/`、`/designs/`、`/photos/`：其他内容归档。
- `/works/`：旧入口，前往随手设计。
- `404.html`：未找到页面。

## 发布与排查

推送 `main` 后，GitHub Actions 会安装锁定依赖、运行测试和内容校验、构建 `dist/`，成功后才更新网站。

- 页面没有更新：确认变更已提交，查看 Pages 工作流是否成功，然后强制刷新浏览器。
- 音乐无法提取：确认是单曲链接；短链失败时粘贴展开后的单曲页面，或手动补充信息。
- 歌曲链接跳错：检查文件名、`songId` 和 `canonicalUrl` 是否一致。
- 封面加载失败：正文和跳转仍会保留；修正封面或使用无封面状态。
- 发布认证失效：本地保存和预览不受影响，修复 Git 凭据后再发布。

修改后至少检查 320、375/390、768、1024 和 1440px 宽度、200% 缩放、键盘焦点、长歌名和无封面状态。正式页面只能使用确认过的真实内容，不添加虚构歌曲、动态、日期、地点、摄影者或设备。
